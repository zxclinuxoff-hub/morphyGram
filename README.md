# MorphyGram

Тёмный премиальный веб-клиент Telegram (PWA) с памятью:

- **Анти-удаление** — сообщения, удалённые собеседником, остаются в чате с меткой «удалено»;
- **История правок** — все предыдущие версии отредактированных сообщений (значок «изменено» кликабелен);
- **Одноразовые медиа** — фото/видео с таймером скачиваются сервером сразу при получении;
- **PWA** — установка на главный экран iPhone / Android / ПК без сторов;
- **Сессии только в RAM** — ничего не пишется на диск.

Технически: Node.js + Express + GramJS (MTProto) + Socket.IO. MTProto-соединение держит
сервер, браузер общается с ним через Socket.IO — никаких проблем с CORS и сборкой в браузере.

---

## Честные ограничения (важно прочитать)

1. **Анти-удаление работает только пока сервер подключён к Telegram** и чат загружался в клиент.
   Telegram не отдаёт удалённое «задним числом». Если сообщение удалили, пока сервер спал
   (бесплатный Render засыпается) — его уже не поймать.
2. **Одноразовые медиа не гарантированы.** Обычно скачивание срабатывает, но Telegram может
   не отдать файл — тогда будет пометка «недоступно».
3. **Нет никакой админ-панели.** Войти можно только в тот аккаунт, чей номер+код введён
   в текущей сессии. Механизма «посмотреть все сессии и зайти в любой аккаунт» в коде
   нет принципиально — это был бы инструмент угона аккаунтов.
4. **Сессии стираются при перезапуске сервера** (RAM-only). После редеплоя или засыпания —
   повторный вход по номеру. Это осознанный компромисс ради приватности.
5. Это неофициальный клиент. Telegram сам выбирает способ доставки кода; часто он приходит в уже авторизованное приложение, а не по SMS. Render может получить ограничения Telegram. Проверь Logs в Render, если запрос отклонён.

## Деплой на Render (пошагово)

### Вариант А — через GitHub (рекомендую)

1. Создай новый **приватный** репозиторий на GitHub и загрузите туда содержимое папки
   (файл `render.yaml` можно не заливать — он для варианта Б):
   ```
   git init
   git add .
   git commit -m "MorphyGram night shift"
   git branch -M main
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/morphygram.git
   git push -u origin main
   ```
   ⚠️ `node_modules` не заливается (есть `.gitignore`). API credentials не хранятся в коде. Используй приватный репозиторий и никогда не публикуй API_HASH.

2. На https://dashboard.render.com — **New → Web Service** → подключи репозиторий.

3. Настройки:
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free

4. В разделе **Environment** добавь `API_ID` и `API_HASH` из своего приложения на https://my.telegram.org/apps. Не вставляй credentials в код или публичный репозиторий. Без этих переменных сервер намеренно не запускается.

5. **Create Web Service** — через минуту-две сайт живой по адресу
   `https://morphygram-xxxx.onrender.com`.

### Вариант Б — Render Blueprint

Если залил `render.yaml`: **New → Blueprint** → выбери репозиторий — Render сам подхватит
настройки сервиса.

### После первого деплоя

1. Открой адрес сайта — увидишь лендинг MorphyGram.
2. **iPhone:** Safari → «Поделиться» → «На экран “Домой”». **Android:** Chrome → ⋮ →
   «Установить приложение». Эта же инструкция есть прямо на сайте.
3. Открой `/app` → номер → проверь код в официальном Telegram на другом устройстве (SMS не гарантируется) → при необходимости введи облачный пароль.

## Как это работает (коротко)

- При входе сервер создаёт GramJS-клиент (MTProto) с твоим api_id/api_hash, код и пароль
  запрашиваются у пользователя через Socket.IO.
- Все исходящие апдейты Telegram обрабатываются на сервере:
  - `UpdateDeleteMessages` / `UpdateDeleteChannelMessages` → сообщение помечается «удалено»,
    но содержимое остаётся в кэше и на клиенте;
  - `UpdateEditMessage` / `UpdateEditChannelMessage` → предыдущий текст уходит в историю правок;
  - медиа с `ttlSeconds` скачиваются сразу в временный каталог (`/tmp/morphygram-media`),
    раздаются по некируемым ссылкам.
- Токен сессии (случайный) отдаётся в localStorage браузера, им же можно восстановить
  сессию после обновления страницы — пока сервер не перезапущен.
- Никаких списков сессий, панелей и «входа в чужие аккаунты» в коде нет.

## Безопасность

- `api_hash` — секрет. Не публикуй репозиторий с зашитым дефолтом, либо задавай его
  через Environment на Render и удали дефолт из `server.js`.
- Не давай ссылку на deployment посторонним: каждый, кто введёт свой номер, войдёт в свой
  аккаунт через ТВОЙ api_id (расход твоей квоты), а все файлы медиа лягут в твой tmp.
- Сессии и скачанные медиа живут в RAM/tmp и стираются при перезапуске.
